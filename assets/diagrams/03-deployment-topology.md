# 图 3：部署拓扑图

**用途：** 展示多个网关与房间服务实例如何承载多个房间，同时共享持久化基础设施。  
**建议报告位置：** 第 2 章“部署与扩展方式”。  
**状态：** 逻辑部署草图；数据库高可用拓扑、具体实例数与编排平台尚未确定。

~~~mermaid
flowchart TB
    CLIENTS["浏览器客户端集合"]
    LB["负载均衡 / WebSocket 接入"]
    subgraph GATEWAYS["网关实例"]
        GW1["网关实例 A"]
        GW2["网关实例 B"]
    end
    subgraph ROOMS["房间服务实例（示意）"]
        R1["房间服务实例 1<br/>房间 101、102"]
        R2["房间服务实例 2<br/>房间 201、202"]
        R3["房间服务实例 N<br/>其他房间"]
    end
    PUB["事件发布器实例"]
    PG[("PostgreSQL<br/>权威持久化层")]
    REDIS[("Redis<br/>在线状态与路由缓存")]
    OBJ[("对象存储<br/>静态地图资源")]
    CLIENTS <--> LB
    LB --> GW1
    LB --> GW2
    GW1 <--> R1
    GW1 <--> R2
    GW2 <--> R2
    GW2 <--> R3
    R1 <--> PG
    R2 <--> PG
    R3 <--> PG
    R1 <--> REDIS
    R2 <--> REDIS
    R3 <--> REDIS
    PUB --> PG
    PUB --> REDIS
    R1 --> OBJ
    R2 --> OBJ
    R3 --> OBJ
~~~

**图示说明：**
- 该图表达逻辑部署关系，不代表必须部署三台房间服务，也不代表网关与房间服务必须一一绑定。
- 同一房间在任一时刻只能有一个有效的权威写入任期；不同房间可由不同实例处理。
- PostgreSQL 主备复制、Redis 高可用和具体故障切换方式暂列为待设计项，不应在最终报告中描述成已经实现。
