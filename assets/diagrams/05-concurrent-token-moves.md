# 图 5：同一标记的并发移动与版本冲突

**用途：** 说明并发请求如何由房间服务判断和排序。  
**建议报告位置：** 第 6 章“同步”。

~~~mermaid
flowchart TD
    A["玩家 A 请求移动标记"]
    B["玩家 B 请求移动同一标记"]
    Q["房间服务按权威顺序处理"]
    V["检查权限、规则和当前状态"]
    C{"操作是否仍然有效？"}
    D["保存已接受的状态变化"]
    E["返回成功并通知有权查看的成员"]
    F["拒绝过期修改，提示刷新状态"]

    A --> Q
    B --> Q
    Q --> V --> C
    C -- 是 --> D --> E
    C -- 否 --> F
~~~

**关键说明：** 客户端时间不决定最终顺序。后到的过期操作不能静默覆盖已提交状态；不需要为每次移动引入完整的分布式互斥协议。
