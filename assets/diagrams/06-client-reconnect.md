# 图 6：客户端断线重连与事件恢复

**用途：** 区分事件补发和快照恢复两条路径。  
**建议报告位置：** 第 8 章“容错与恢复设计”。  
**状态：** 与通信协议草案一致；事件保留策略仍待确认。

~~~mermaid
flowchart TD
    A["客户端重新连接<br/>发送 roomId 与 lastSequence"]
    B["验证身份、成员状态与当前可见权限"]
    C["查询房间当前 sequence 与事件保留范围"]
    D{"缺失事件是否仍在日志中？"}
    E["按 sequence 顺序补发缺失事件"]
    F["生成当前权限下的快照投影"]
    G["从 snapshotSequence + 1 补发后续事件"]
    H["客户端校验并应用事件，更新 lastSequence"]
    I["恢复完成"]
    A --> B --> C --> D
    D -- 是 --> E --> H --> I
    D -- 否 --> F --> G --> H --> I
~~~

**关键说明：**
- 只有当前仍有房间访问权限的客户端才可以恢复该房间状态。
- 快照的状态内容与 snapshotSequence 必须对应同一一致性视图。
- 快照必须按当前权限生成；不能把含完整隐藏区域的内部状态发给普通玩家。
- 如果客户端发现序号缺口或状态校验失败，不应静默跳过缺失事件。
