# 图 8：按成员权限生成状态投影

**用途：** 展示为什么不能把房间完整内部状态直接广播给所有成员。  
**建议报告位置：** 第 2 章安全边界、第 4 章消息通信或第 8 章恢复设计。  
**状态：** 设计草图；具体视野与迷雾规则待需求确认。

~~~mermaid
flowchart LR
    EVENT["内部权威事件 / 快照"]
    AUTH["读取当前成员身份、角色与权限"]
    PROJECT["服务端按接收者生成可见状态投影"]
    HOST["主持人视图<br/>按主持人权限展示"]
    PLAYER["玩家视图<br/>仅包含获授权的场景信息"]
    OBS["观察者视图<br/>只读且受房间规则限制"]
    EVENT --> AUTH --> PROJECT
    PROJECT --> HOST
    PROJECT --> PLAYER
    PROJECT --> OBS
~~~

**关键说明：**
- 隐藏信息必须在服务端过滤，而不是先发送给客户端再由前端隐藏。
- 事件、快照、错误消息和日志都可能成为信息泄漏路径。
- 若最终需求不包含观察者角色，应同步删除该分支，避免需求与图示不一致。
