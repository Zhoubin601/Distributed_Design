# 设计图规划与 Codex 整合说明

> 版本：v0.1  
> 当前阶段：计划与设计素材准备。尚未进入最终课程设计 Word 的整合与排版阶段。

## 1. 当前工作原则

本项目按“原始资料 → 过程整理 → 用户确认 → 最终交付”的顺序推进。

- raw/ 中的课程课件、作业要求、模板和附录图片是原始资料，不修改、不覆盖。
- docs/ 存放需求、技术判断、知识点映射、接口/数据设计和图表清单等过程材料。
- assets/diagrams/ 存放可复用、可审阅的 Mermaid 图源。图源是设计素材，不是最终排版图片。
- output/ 只用于最终确认后生成的交付文件。当前阶段不生成最终 Word。
- 最后由 Codex 读取已确认的计划、图源、设计文档和原始模板，统一术语、图号、引用和版式，生成最终报告。

| 阶段 | 目标 | 主要产物 | 进入下一阶段的条件 |

- `docs/technology-comparison.md`：按 Chapter 1–8 整理方案比较、推荐基线、不采用的机制及设计边界。该文档是规划和论证素材，不替代课堂 PDF 的正式引用。

## 5. 设计图的统一规则

1. 统一使用“房间服务”“房间协调者”“房间序号 sequence”“对象版本 version”“操作标识 operationId”“协调者任期 epoch”等术语。
2. 区分逻辑架构图和部署拓扑图：前者说明职责与调用关系，后者说明实例如何部署与共享基础设施。
3. 每张时序图都应明确请求方、权威校验点、持久化点、响应点和异步通知点。
4. 不把 Redis Pub/Sub 描述为可靠事件日志；持久事件应能从 PostgreSQL 恢复。
5. 不把“发送成功”写成“所有客户端已收到”，不把“最终一致”写成“任意时刻完全一致”。
6. 不把候选机制写成已实现功能。数据库复制模式、选举算法、快照周期、保留期限和性能指标未确认前都应标记为设计假设或待确认。
7. 涉及战争迷雾的图必须体现服务端授权过滤，不能只依赖前端隐藏。
8. Mermaid 图源优先保留为可编辑文本；最终报告需要图片时，由 Codex 按模板渲染为 SVG/PNG 或使用兼容的文档插图方式，并检查中文字体、清晰度和图注。

- [ ] 用户确认每房间人数、延迟与恢复时间等目标是否作为设计假设。
- [ ] 图中的组件、接口和数据表与 docs/system-design.md、docs/database-design.md、docs/communication-protocol.md 一致。
- [ ] 每张图都有用途、建议放置章节和图注含义。
- [ ] 图号在最终 Word 中按出现顺序统一。
- [ ] 课程 Chapter 1–8 的关键机制有“应用或比较 + 选择理由”，不是只在图中出现术语。
- [ ] 正式写作使用 raw/课程设计模板.docx，且不修改 raw/不允许修改附录.jpg 所要求的附录结构。
- [ ] 当前规划和图源得到用户确认后，才开始最终 Word 整合。
